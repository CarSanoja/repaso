# Agents for Humans: The tests that made Repaso change its product claims

Repaso's strongest review findings came from cases where a plausible feature did not do what its description suggested. A button selected a teacher note, but the system sent only an acknowledgment. A rejected human review did not become an incorrect learning outcome. A family deletion left material bytes and generated items behind. Each required a change in behavior and a check of the resulting effects.

The most expensive finding could not have come from a test. Every offline test hands an agent a model answer that is already a valid object, so the suite can check what the code does with a generated batch and never whether a real model can produce one. A small live tier exists for that single question. The first time it asked, the generating model answered a null list of options for every open question — which is correct, because an open question has no choices, and which a field typed as a list of strings rejects. The batch failed to parse and item generation returned nothing. Every batch the planner asks for contains open questions, so in the cloud no practice would ever have been written, and nothing in the offline suite could have said so. The fix is at the schema base: a null list is now read as the empty list it means. The change record `0ca2454` carries the run that found it, and `tests/agents/test_base.py` is the regression that keeps it.

One finding changed an evaluation idea. The old answerability probe saw a math question and its options, was forced to guess and could reject the item after one correct answer. That does not establish a defective exercise. Prior knowledge may be exactly what practice is meant to use, and a guess can be right by chance.

The new probe sees only the options and may abstain. Its result is advisory. It cannot veto an otherwise valid exercise simply by guessing correctly. The ablation has since run: critic-only review, the old forced-choice veto and options-only advice over thirty frozen items in three option orders, ninety decisions an arm. The advisory probe changed none of them, and it answered UNKNOWN on twenty-three of the twenty-four decisions carrying the exact clue its prompt names. It ran with one substitution that limits everything it can say — no teacher was available, so validity and option clues are labelled from the defects the harness itself planted. Retention and rejection are therefore about plants, not about whether a question is good, and the teacher-labelled version of the experiment is still owed. No improvement in educational quality is claimed.

The grading evaluation has a similar boundary. A valid JSON response is useful technical evidence; it is not evidence that a child was graded correctly. A model's 0.85 confidence is not a calibrated probability. Repaso therefore includes 60 synthetic answer examples, split by question group into development and held-out sets, and a blind teacher-review file without author labels or model predictions.

Those independent labels are blank today. The development half has since been graded against live inference, so the scorer now has thirty real predictions to work with, and every figure it reports over them is agreement with the labels the author proposed for their own answers — which the tool names in its own output and refuses to promote into independent agreement. It reports coverage, reviewed sample counts, false automatic-correct decisions, confidence bands and uncertainty intervals. The interval is the part worth reading: zero automatic decisions wrongly called correct, out of eight called correct, bounds that error at thirty-two percent. Empty data does not become perfect accuracy, and a small clean sample does not become a low rate.

The evidence register also separates four levels. Ordinary tests verify software behavior. A 14-day authored simulation exercises 30 synthetic students and 420 local sessions, with 1,037 responses and all nine scenario gates satisfied. A separate actual Textract call recognized a new printed Spanish fractions page, and a bounded live run confirmed that each configured model answers and fills its schema. That last result is about a contract, not about a grade. The demonstration journey now replays model outputs recorded from Amazon Bedrock, which records what the models returned on one day and measures neither quality nor family outcome; both remain unmeasured while independent review is pending.

This distinction affects the product promise. The candidate accepts printed fourth-grade math material and a one-page PDF. Voice and Spanish handwriting are excluded. Deletion covers active state and material versions, while consent explains operational-log, backup and Telegram retention. A small shared-section threshold is not described as formal anonymity.

The family pilot is designed to expose added work as well as savings. It records minutes spent preparing, accompanying, reviewing and fixing mistakes, along with operator assistance and incomplete sessions. A family choosing to use the routine tomorrow would be useful evidence; a learning-effect claim would require a different study.

These corrections make the project easier to judge. The goal is to make the product, demonstration and evidence describe the same system—even when the honest result is that a promising idea still needs a real test.
